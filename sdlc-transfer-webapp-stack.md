## Pattern Summary

### Structure

**Workspace layout** — pnpm monorepo with three packages: `@team-manager/backend` (NestJS), `@team-manager/frontend` (React 19 + Vite), `@team-manager/ui` (minimal daisyUI component stub).

**Backend** (NestJS 11, Node 26, TypeScript):
- Entry point imports `./tracing` first so OTel SDK starts before any I/O.
- `AppModule` composes: `ConfigModule` (global), `DatabaseModule` (TypeORM + Postgres), `HealthModule`, `UsersModule`, `AuthModule`.
- `SanitizeBodyMiddleware` applied globally to block prototype-pollution keys (`__proto__`, `constructor`, `prototype`).
- `ValidationPipe` with whitelist + forbidNonWhitelisted + transform; `HttpExceptionFilter` for structured error JSON.
- Auth flow: register → bcrypt hash (cost 12) → JWT; login → bcrypt compare → JWT. JWT validated via `JwtStrategy` (passport-jwt, Bearer extraction). `JwtAuthGuard` + `RolesGuard` available to decorate individual routes.
- Health endpoint at `/health` uses `@nestjs/terminus` + TypeORM ping check.
- Swagger at `/api/docs`.

**Tracing** (three-signal OTel): traces + metrics + logs exported via OTLP-HTTP to OpenObserve. All credentials read from env; no hardcoded secrets. `SIGTERM` triggers `sdk.shutdown()` before process exit to flush in-flight batches. Wrapped in try/catch so a broken OTel endpoint never crashes the app.

**Frontend** (React 19, Vite, Tailwind 4, daisyUI 5):
- `telemetry.ts` imported as the first statement in `main.tsx` — OpenObserve RUM + logs SDKs init before React mounts.
- nginx.conf: SPA fallback, `/api/` proxy to backend FQDN, `/rum/` + `/api/default/rum/` proxies to in-cluster OO, security headers (CSP, X-Frame-Options, X-Content-Type-Options, Referrer-Policy).
- MSW wired with an empty `handlers.ts` — extend when mocking API calls in tests.

**K8s** (Docker Desktop / Skaffold):
- Namespace `team-manager`; Postgres (StatefulSet, 10Gi PVC), OpenObserve (Deployment, emptyDir `/data`), backend (Deployment × 2 replicas), frontend (Deployment × 2 replicas, nginx).
- All secrets generated by `make secrets` from `k8s/secrets.example.yaml` (gitignored). Three secrets: `postgres-secret`, `backend-secret`, `openobserve-secret`.
- Backend ConfigMap holds non-sensitive OTel env vars; `JWT_SECRET`, `DATABASE_URL`, `OTEL_EXPORTER_OTLP_PASSWORD` come from Secrets.
- Security hardening: `runAsNonRoot`, `allowPrivilegeEscalation: false`, `capabilities.drop: [ALL]`, `readOnlyRootFilesystem: true` (backend only; OO root stays writable for `/data`).

**CI** (GitHub Actions, ubuntu-24.04, Node 26):
- Jobs: lint → typecheck → test-unit → test-integration (parallel) → build-backend + build-frontend → vulnerability-scan (Trivy) + SBOM (Syft) → test-e2e (Playwright).
- Docker layer caching via GitHub Actions cache.

### Invariants

1. Tracing must import before all other server code — `import './tracing'` is the first line of `main.ts`.
2. Secrets never in committed files — only `secrets.example.yaml` with `CHANGE_ME_*` placeholders is tracked.
3. Backend authenticates to OO via Basic auth built at runtime from injected env vars, never hardcoded.
4. `make secrets` is idempotent — skips if `k8s/secrets.yaml` already exists.
5. OTel SDK start errors are caught; process continues without telemetry rather than crashing.
6. `SIGTERM` handler flushes OTel batches before exit.
7. Prototype-pollution keys rejected at request ingress (`SanitizeBodyMiddleware`).

### Edge cases preserved

- OO requires writable `/data` — emptyDir volume, root filesystem NOT set read-only on OO container.
- RUM `defaultPrivacyLevel: 'mask-user-input'` — safer default; per-deployment teams can downgrade.
- nginx security headers omitted from proxy location blocks (nginx stops inheriting parent `add_header` once a location adds its own).
- Frontend Dockerfile copies `packages/ui` so the workspace dependency resolves inside the container.

### Dependencies

- OpenTelemetry SDK Node 0.217.0 track (traces + metrics + logs)

- OpenObserve browser SDK 0.3.x (RUM + logs)
- Docker Desktop Kubernetes + Skaffold ≥ 2 for the k8s dev loop
- Trivy + Syft in CI for vulnerability scanning + SBOM

## Departures from the Exemplar

1. **`@webapp/*` → `@team-manager/*` scope throughout.** All package names, Docker image names, K8s namespace, in-cluster DNS hostnames, OTel service names, and RUM application IDs adapted.

2. **`@openobserve/browser-{rum,logs}` downgraded from `^0.4.0` → `^0.3.1`.** The exemplar pins `^0.4.0` but that version does not exist on npm (latest is 0.3.1). This is a pre-existing defect in the exemplar acknowledged in its observability transfer note.

3. **`packages/ui` is a minimal two-component stub (Button, Card) rather than the full 69-component library.** The full component library is a separate transfusion concern (stack-react → stack-webapp, documented in `sdlc-transfer-component-library.md`). The stub provides the same import surface (`import { Button, Card } from '@team-manager/ui'`) and wire-compatible props so it can be replaced by the full library without changing callers.

4. **`packages/ui` adds its own test infrastructure** (`vite.config.ts` with `@vitejs/plugin-react`, `test-setup.ts` with jest-dom, `vitest` + `@testing-library/react` as devDependencies). The exemplar's `packages/ui` inherits its test tooling from the larger workspace setup; the target's stub is self-contained.

5. **Frontend Dockerfile copies `packages/ui`** in both `dev` and `builder` stages. The exemplar's frontend Dockerfile did not need this because `packages/ui` was already in the monorepo with its own build; the target's frontend depends on the new stub package which must also be present in the Docker build context.

6. **`Makefile` references `@team-manager/*` filter names.** Cosmetic — same targets, same semantics.

7. **`docker-compose.yml` DB name/user `webapp` → `team-manager`.** Default dev credentials adapted; no semantic change.

8. **Storybook CI job omitted.** The exemplar's `storybook-test` job in `ci.yml` was introduced by the component-library transfusion from `stack-react`. The target's minimal UI stub has no Storybook; the job is omitted. Re-add when Storybook is transfused.

9. **`Makefile` `doctor` target omits the NestJS/Node version check.** The exemplar's doctor also checked the Node version against a specific pin; the target's `package.json#engines` constraint already enforces this at install time.

10. **`k8s/secrets.yaml` is gitignored from the start.** The exemplar had this in `.gitignore`; copied as-is.

## Propagation Hooks

- **Backend entry point contract:** any new NestJS app in this workspace should follow `import './tracing'` as the first line of `main.ts` and wire the same four OTel env vars (`OTEL_EXPORTER_OTLP_ENDPOINT`, `OTEL_EXPORTER_OTLP_USER`, `OTEL_EXPORTER_OTLP_PASSWORD`, `OTEL_SERVICE_NAME`).
- **Secret bootstrap pattern:** `Makefile :: secrets` + `k8s/secrets.example.yaml` is the canonical pattern. Add a `CHANGE_ME_<KEY>` placeholder to the template and a `sed` substitution line in the Makefile target.
- **UI package surface:** `import { Button, Card } from '@team-manager/ui'`. Add new components under `packages/ui/src/components/<Name>/` and re-export from `packages/ui/src/index.ts`. When the full component library is transfused from `stack-webapp/packages/ui`, replace this stub in-place.
- **Port-forward map (Skaffold):** `frontend → 5173`, `backend → 3000`, `openobserve → 5080`. New long-running services should claim a port and register in `skaffold.yaml :: portForward`.
- **DatabaseModule entity list:** Add new TypeORM entities to the `entities` array in `apps/backend/src/database/database.module.ts`.
