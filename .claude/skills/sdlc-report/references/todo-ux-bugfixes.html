07-security-privacy.md React auth: lazy useState init vs. useEffect

When a React component must synchronize a module-level singleton (e.g., an API client's _token field) with React state on mount, use the useState lazy initializer — not useEffect.

The lazy initializer fires synchronously before any child renders; useEffect fires after children mount, so child useEffects (e.g., fetchTodos) can fire before the parent sets the token — causing an auth race: the first API call has no Authorization header → 401 → forced logout.

// ✅ Correct
const [token, setLocalToken] = useState<string | null>(() => {
  const t = sessionStorage.getItem('access_token');
  setToken(t); // synchronously updates module-level singleton
  return t;
});
// ❌ Anti-pattern: useEffect fires AFTER children, causes race condition

Security implication: the anti-pattern is exploitable as a denial-of-session — any authenticated user who reloads the page is immediately logged out.

07-security-privacy.md useLayoutEffect for DOM focus after edit transitions

When transitioning from view-mode to edit-mode by setting state, use useLayoutEffect for focus management — not useEffect and not setTimeout(fn, 0).

useLayoutEffect fires synchronously after DOM mutations but before the browser paints. useEffect fires asynchronously and can miss the focus if the browser dispatches a blur event from the triggering click before the effect runs.

// ✅ Correct
useLayoutEffect(() => {
  if (editing && editRef.current) {
    editRef.current.focus();
    editRef.current.select();
  }
}, [editing]);
06-test-strategy.md Throttle-aware E2E login strategy

When the login endpoint has a strict rate limit (e.g., 5 req / 15 min, in-memory per pod), E2E tests must not call the login API once per test. Use this pattern:

1. beforeAll: obtain one JWT via a direct API call (counts 1 against the throttle).
2. Per test: inject the JWT via page.addInitScript → sessionStorage.setItem('access_token', token) before page.goto('/').
3. afterEach: clean up via direct API calls using the beforeAll token (no additional logins).

This pattern uses exactly 1 login per test file run, regardless of how many tests need auth. Requires React auth context to use a useState lazy initializer — not useEffect.

06-test-strategy.md Docker/k8s image freshness check before E2E runs

Docker Desktop's k8s uses containerd's image store, separate from the Docker daemon's store. Running docker build --no-cache does not guarantee k8s uses the new image for the same tag — containerd caches the prior digest independently.

Before E2E tests: verify the deployed bundle matches current source with kubectl exec. If mismatched, use kubectl cp dist/ <pod>:/usr/share/nginx/html/ for immediate fix, or rebuild with a new tag.

Preferred: use skaffold dev — builds with content-addressed tags and syncs to k8s automatically.

08-operational-readiness.md NestJS in-memory throttle resets on pod restart

@nestjs/throttler defaults to an in-memory store: throttle state is lost on pod restart, and each replica in a multi-pod deployment has an independent bucket.

For production multi-pod setups, configure a Redis store via ThrottlerStorageRedisService. For single-pod demo deployments, document that kubectl rollout restart resets the throttle — useful for clearing test-induced exhaustion.
